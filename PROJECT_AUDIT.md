# Swift TCG — Project Audit

**Audited:** 2026-08-06  
**Version:** `0.1.0` (`package.json`)  
**Scope:** Current codebase only. No invented features. Stubs, placeholders, incomplete wiring, and unused code are called out explicitly.

---

## Snapshot

Swift TCG is a Next.js App Router headless storefront for sealed Japanese (and multi-language) TCG product — primarily Pokémon and One Piece. Shopify is the **single source of truth** for storefront products, cart, search, collections, Online Store pages, shop policies, and marketing CMS (metaobjects). Local `data/*.json` files are **importer/offline dumps only** and are not read by the storefront runtime.

| Layer | Actual state |
| --- | --- |
| Framework | Next.js `16.3.0` (App Router), React `19.2.8`, TypeScript |
| Styling | Tailwind CSS v4, `tw-animate-css`, design tokens in `lib/design.ts` / `docs/DESIGN.md` |
| UI primitives | shadcn/ui (`components/ui/button.tsx`), `@base-ui/react`, `lucide-react` |
| Catalog (runtime) | Shopify Storefront API only — mapped to `@/types/product` |
| Catalog (offline) | `data/*.json` written by SORA importer; not used by `app/` loaders |
| Shopify reads | Products, collections, facets, homepage rails, search, pages, policies, metaobjects |
| Shopify writes (runtime) | Cart create / lines add / update / remove via Storefront Cart API |
| Shopify writes (ops) | Admin API: product sync, collections, content seed, CMS setup |
| Cart | Shopify-backed; browser stores only cart id in `localStorage` |
| Checkout | Redirect to Shopify `checkoutUrl` |
| Auth (storefront) | None — no customer accounts |
| Auth (importer) | Playwright session cookies for SORA B2B; Admin client-credentials for sync |
| Hosting intent | Vercel (documented; standard Next config) |
| React Compiler | Enabled in `next.config.ts` |
| Images | `cdn.shopify.com/s/files/**` allowed in `next.config.ts` |

| Surface | Source | Fallback |
| --- | --- | --- |

| Footer social / contact | Shop metafields namespace `swift` | Empty / defaults when unset |

There are **12 page routes** (some with dynamic segments) and **2 API routes**. There is **no** nested layout beyond the root layout. The `(store)` route group does not change the URL. There is **no** `middleware.ts`, `not-found.tsx`, `loading.tsx`, `error.tsx`, or `global-error.tsx`.

Dedicated static files `app/pokemon/page.tsx` and `app/one-piece/page.tsx` have been **removed**; those URLs are served by dynamic `app/[game]/page.tsx`.

### Page details

#### `/` — Homepage

- **Renders:** `StoreChrome` → `Hero` → Coming Soon carousel (`id="preorders"`) → `ShopByCategory` → `TrustSection` → Newest Arrivals carousel → `Newsletter`
- **Data:** `getShopifyComingSoonProducts(8)`, `getShopifyNewestArrivals(8)`, `getHomepageHeroSlides()`, `getHomepageCategoryCards()`
- **SEO:** Inherits root placeholder metadata
- **Special:** Coming Soon “View all” → `/preorders`; Newest Arrivals → `/new-releases`

#### `/{game}` — TCG game landing

- **Examples:** `/pokemon`, `/one-piece` (any discovered primary TCG collection)
- **Renders:** `CollectionView` (hero + language cards + optional browser)
- **notFound:** Reserved handle, missing Shopify collection, or loader returns null
- **Special:** If ≥2 language facets → `requiresLanguagePick`; product grid hidden until language chosen. Single-language games load parent products immediately.

#### `/{game}/{language}` — Language catalog

- **Examples:** `/pokemon/japanese`, `/pokemon/korean`
- **Data:** Products from Shopify child collection handle `{game}-{language}`
- **notFound:** Invalid/empty language facet

#### `/new-releases` family

- Maps to Shopify collection handle **`new-arrivals`** (app path stays `/new-releases`)
- Flow: TCG pick → language pick → products (`requiresGamePick` / language pick when facets exist)
- `hideEmptyLanguages` enabled

#### `/preorders` family

- Maps to Shopify collection handle **`preorders`**
- Same hierarchical browse flow as new-releases

#### `/products/{slug}` — PDP

- **Data:** Shopify by handle only; related via `getShopifyRelatedProducts({ handle, category, limit: 5 })`
- **UI:** Breadcrumb → `ProductGallery` + sticky `PurchasePanel` → `ProductDetails` → related `ProductCarousel` → `RecentlyViewed` → `Newsletter`
- **notFound:** Product missing
- **SEO:** No `generateMetadata`
- **Breadcrumb category:** Binary — category string matching One Piece → `/one-piece`, else `/pokemon`

#### `/pages/{handle}` — Content pages

- **Canonical paths** (`CONTENT_PAGE_PATHS`): `/pages/about`, `/pages/contact`, `/pages/faq`, `/pages/preorder-policy`
- **SEO:** `generateMetadata` from Shopify SEO / title / body summary
- **Layouts by handle:**
  - `about` → `AboutPageContent` (hard-coded layout; Shopify body unused)
  - `contact` → contact UI + shop/page metafields
  - `faq` → `FaqPageContent` via `parseFaqHtml`
  - `preorder-policy` → `PolicyPageContent`
  - else → title + `RichHtml`

#### `/policies/{handle}` — Shop policies

- **Canonical paths** (`POLICY_PATHS`): shipping, refund, privacy, terms under `/policies/...`
- **Handle → kind:** `privacy-policy`, `refund-policy`, `shipping-policy`, `terms-of-service`
- **SEO:** `generateMetadata` → policy title

### API routes

#### `GET /api/search`

- Query: `q` (empty → `[]`), `limit` default 12, clamped 1–24
- Returns `{ products: Product[] }`
- `dynamic = "force-dynamic"`

#### `GET` / `POST /api/cart`

- **GET** `?cartId=` — fetch Shopify cart; missing/expired → empty payload (200). Buyer IP from `x-forwarded-for` / `x-real-ip`
- **POST** actions: `add` | `update` | `remove` | `clear`
- Statuses: 400 invalid; 404 not_found; 409 mixed_cart / sold_out / inventory / invalid; 502 ShopifyClientError; 500 other
- `dynamic = "force-dynamic"`

### Valid game / language handles

Handles are **Shopify-discovered**, not hardcoded in route files.

**Reserved** (`lib/shopify/reservedHandles.ts`) — never treated as a TCG game under `/[game]`:  
`api`, `products`, `preorders`, `new-releases`, `new-arrivals`, `coming-soon`, `featured`, `best-sellers`, `bestsellers`, `sale`, `accessories`, `sealed-cases`, `cases`, `booster-cases`, `cart`, `checkout`, `account`, `search`, `pages`, `policies`, `about`, `contact`, `faq`, `preorder-policy`, `privacy-policy`, `refund-policy`, `shipping-policy`, `terms-of-service`, `favicon.ico`.

**Primary TCG discovery:** collections that have at least one child `{handle}-*` collection.  
**Language facets:** child collections `{game}-{language}`. Documented examples: Pokémon `japanese` / `english` / `korean` / `chinese`; One Piece `japanese` / `english`. Any other `{game}-{slug}` child also becomes a facet.

### Not present as routes

- No `/cart` or `/checkout` pages (drawer + Shopify hosted checkout)
- No `/account`, login, or register
- No `/search` results page (modal + API only)
- No `/accessories` page (handle reserved; CMS/category links still use `#accessories`)
- No root `/about`, `/contact`, etc. — content lives under `/pages/…` and `/policies/…`
- No custom 404 / loading / error boundaries

### Hash / unresolved links (present in code)

| Link | Where |
| --- | --- |
| `#accessories` | CMS / homepage category fallbacks in `storefrontCms.ts` |
| `#pokemon`, `#one-piece` | Hero secondary CTAs in `HOMEPAGE_SLIDE_DEFS` |
| `#preorders` | Homepage Coming Soon section (`id="preorders"`) — **resolves** |

Footer and Navbar use real paths (`/pages/…`, `/policies/…`, `/pokemon`, etc.), not the old `#about`-style placeholders.

## Features

Implemented features present in the current codebase:

1. **Homepage** — Hero carousel, Coming Soon rail, Shop by Category, Trust strip, Newest Arrivals, newsletter UI
2. **TCG collection browse** — Dynamic `/{game}` and `/{game}/{language}` with Shopify-discovered games and language facets
3. **Merch collections** — Preorders and New Releases with hierarchical game → language → products flow
4. **Collection UX** — Client search, availability/price/type/year filters, sort, grid density, pagination (24/page)
5. **Product cards** — Status badges, pricing / Coming Soon, quick view, add-to-cart / preorder CTAs
6. **Product detail pages** — Gallery, purchase panel, generated description/specs, related products, recently viewed
7. **Global search** — Keyboard-opened dialog + `/api/search` backed by Shopify
8. **Shopify Cart** — Create/add/update/remove/clear; inventory-aware qty caps; checkout redirect
9. **Mixed-cart policy** — Blocks mixing preorder and in-stock lines (client dialog + server 409)
10. **Store chrome** — Announcement bar, sticky navbar, footer with real content/policy links
11. **Content pages** — About, Contact, FAQ, Preorder Policy from Shopify pages
12. **Shop policies** — Shipping, Refund, Privacy, Terms from Shopify policies
13. **Storefront CMS** — Metaobject heroes/visuals with local asset fallbacks (`docs/STOREFRONT_CMS.md`)
14. **SORA importer** — Authenticated scrape → local images + JSON dumps → Shopify Admin sync
15. **Pricing engine** — Wholesale JPY → retail USD charm pricing for import (`lib/pricing`)
16. **Content seeding / CMS setup scripts** — Admin bootstrap for pages, policies, metafields, metaobjects
17. **Smoke-test scripts** — Storefront products and content connectivity checks

**Not implemented:** customer accounts, wishlist, newsletter backend, dedicated accessories page, dedicated cart/checkout pages, storefront customer auth, automated test suite.

## Product System

### Runtime model

`types/product.ts` — `Product`:

| Field | Notes |
| --- | --- |
| `id` | Shopify product GID |
| `slug` | Handle |
| `title` | Title |
| `category` | Inferred brand/category string (not raw Shopify `productType`) |
| `image` | Featured image URL |
| `price` | Min variant price (number) or null |
| `url` | Storefront product path |
| `status` | `instock` \| `preorder` \| `soldout` \| `unknown` |
| `vendor?` | Shopify vendor |
| `tags?` | Shopify tags |
| `releaseDate?` | ISO date from `custom.release_date` |

`CatalogCategory` type remains `"pokemon" | "onepiece"` for some helpers; UI category strings can be broader.

### Mapping (`lib/shopify/mappers.ts`)

- Status from tags `preorder` / `pre-order`, else sold out if unavailable, else in stock
- Category inferred from tags / vendor / title / handle
- Release date from metafield when present

### Presentation helpers (`lib/catalog/`)

These **do not load** products from JSON or Shopify. They operate on already-mapped `Product` objects:

| Module | Role |
| --- | --- |
| `collections.ts` | Presentation chrome for pokemon / one-piece / preorders / new-releases (atmosphere, collage, copy) |
| `collectionFilters.ts` | Search, filter, sort, `PAGE_SIZE = 24`; `newest` sort is a no-op (keeps source order) |
| `productMeta.ts` | Brand/type/availability/CTA/purchasable helpers |
| `getProductDescription.ts` | Templated paragraph copy from title/category |
| `getProductSpecs.ts` | Derived specs; **Language always `"Japanese"`** |
| `homepage.ts` | Release-date helpers: prefer metafield; else hardcoded slug map + “Ships on …” title parse (year hard-coded `2026` in parser) |

### Images

`getProductImages` returns a single-image array from the catalog featured image. Comment notes readiness for multi-image; Storefront product queries do not fetch full media galleries for the Product model.

### Descriptions

Storefront product queries **omit** `descriptionHtml`. PDP and Quick View use generated templates. Admin sync **writes** generated HTML to Shopify at import time; the storefront does not re-read merchant-edited bodies for PDP.

### Offline JSON (`data/`)

Files present / written by importer:

- `data/pokemon.json`
- `data/pokemon_cn.json`
- `data/pokemon_kr.json`
- `data/onepiece.json`

Shape includes `id`, `slug`, `title`, `category`, `image`, `cost`, `price`, `url`, `status` (CN/KR also `language`). **Not imported by storefront loaders.**

### Pricing (`lib/pricing/`)

- FX `USD_PER_JPY = 0.006344`
- Markup 1.6 below $50 cost, else 1.45; charm `.99`
- `formatUsdPrice` → “Coming Soon” when null
- Used by importer / `apply-pricing`; storefront displays Shopify variant prices after mapping

## Search

### Global search

| Piece | Behavior |
| --- | --- |

## Collections

### Standard collections (`lib/shopify/standardCollections.ts`)

Defined for sync/ensure:

- **Primary:** `pokemon`, `one-piece`, `accessories`, `sealed-cases`
- **Language children:** e.g. `pokemon-japanese`, `pokemon-korean`, …
- **Homepage / merch:** `featured`, `new-arrivals`, `preorders`, `coming-soon`, `best-sellers`, `sale`

**Homepage rails currently use** Coming Soon (`preorders` / preorder tags) and Newest Arrivals (sorted in-stock products). Collections `featured`, `best-sellers`, and `sale` are ensured/reserved but **not loaded by homepage rails**.

### Browse hierarchy

- `browseHierarchy.ts` — discover primary TCGs; filter by game/language; build facets
- `collectionFacets.ts` — language facets from `{parent}-{facet}` children; enrich counts
- `tcgPages.ts` — `loadTcgCollectionPage` for `/{game}` routes
- `merchPages.ts` — `loadMerchCollectionPage` for preorders / new-releases (`new-releases` → Shopify `new-arrivals`)

### Presentation

`lib/catalog/collections.ts` supplies atmosphere gradients and collage images for known collection ids. CMS heroes/visuals overlay via `applyStorefrontHeroToPresentation` / visual key helpers.

### Accessories

Shopify collection key `accessories` exists in the standard set and CMS seeds. There is **no** `app/accessories` page; reserved handle prevents `/[game]` collision. Homepage/CMS links still point at `#accessories`.

### Product fields fetched for catalog

### Sync behavior (`sync.ts`) — evidence summary

- Hybrid release workflow via tags (`ready-to-release`, `release-approved`, sticky `released`)
- Tags include game, language, preorder/soldout/coming-soon, product-type, set code, workflow tags
- Dry-run supported; abort on auth failure

## Cart

### Architecture

| Concern | Owner |
| --- | --- |
| Line items, quantities, subtotal, checkout URL | Shopify Cart API |
| Browser persistence | Cart id only — `localStorage` key `swift-tcg-shopify-cart-id` |
| Legacy cleanup | Removes old full-cart JSON key `swift-tcg-cart` if present |
| Client state | `CartProvider` + `cartReducer` (`HYDRATE`, `SET_CHECKOUT_URL`) — no optimistic local line mutations |
| Server bridge | `app/api/cart` so private Storefront tokens never hit the browser |

### Client modules (`lib/cart/`)

| File | Role |
| --- | --- |
| `CartProvider.tsx` | Context; hydrate; queued POSTs; mounts `MixedCartDialog` |
| `cartReducer.ts` | State + itemCount/subtotal helpers |
| `types.ts` | Cart item / API / context types |
| `mixedCart.ts` | Kind mapping, add-allowed checks, mixed-cart detection, message |
| `useCart.ts` | Hook |
| `index.ts` | Barrel |

### Flow

1. Hydrate: read cart id → `GET /api/cart?cartId=`
2. Mutate: `POST /api/cart` with `add` | `update` | `remove` | `clear`
3. Checkout: `CartDrawer` → `window.location.assign(checkoutUrl)` when present (button disabled if missing)

### Mixed cart (preorder vs in-stock)

- Line attribute `_status` = `preorder` | `instock`
- Client: `wouldCreateMixedCart` → dialog (“Clear cart and add item” or continue)
- Server: `cartHasMixedConflict` / `mixed_cart` 409 unless `skipMixedCheck` after clear
- Same product id may increase qty even across statuses (explicit exception)
- Sold-out / unpriced / unknown cannot add

### UI

- `CartButton` — count after hydrate
- `CartDrawer` — lines, qty caps via `quantityAvailable`, clear, checkout
- `MixedCartDialog` — conflict UX

### `scripts/import-sora.ts`

**Purpose:** Authenticated SORA crawl → local images + JSON dumps → Shopify Admin product sync.

**Catalogs:** `pokemon`, `pokemon_cn` (chinese), `pokemon_kr` (korean), `onepiece`.

**Pipeline per catalog:**

1. Load env; verify Admin auth (warns if missing)
2. `createSoraRequest()` (Playwright session)
3. Paginate `https://sora-cardshop.com/catalog/{slug}` (`MAX_PAGES = 100`)
4. Parse product cards → id, title, image, wholesale JPY, status
5. Enrich unknown status from product pages
6. Slugify; unique across catalogs; price via `priceFromWholesaleJpy`
7. Download images to `public/products/` (never overwrites; 300ms delay)
8. Write `data/{slug}.json`
9. `syncProducts()` → Admin create/update + collection assignment

**Flags:** `DRY_RUN=1`, `--dry-run`, `SHOPIFY_DRY_RUN=1`  
**Side effect:** Always dumps first Pokémon catalog page HTML → `debug/pokemon-page.html`

### `scripts/sora-auth.ts`

Exports: `ensureAuthFiles`, `isSoraSessionValid`, `interactiveSoraLogin`, `ensureSoraAuth`, `createSoraRequest`, URL constants.

### `scripts/apply-pricing.ts`

Reprices existing `data/*.json` rows from `cost` / wholesale heuristics. No Shopify calls. No npm script.

### `scripts/test-shopify.ts`

Storefront smoke test: first 10 products.

### `scripts/test-shopify-content.ts`

Storefront content smoke test: shop name, four policies, `swift.*` metafields, pages about/contact/faq/preorder-policy.

### `scripts/seed-shopify-content.ts`

Admin seed: Online Store pages, legal policies (privacy left alone if present), shop metafield definitions + starter values. Flags: `--dry-run`, `--overwrite-pages`, `--overwrite-contact`.

### `scripts/setup-storefront-cms.ts`

Idempotent CMS bootstrap: metaobject definitions `storefront_hero` / `storefront_visual`, product metafield `custom.release_date`, seed entries, upload matching `/public` assets to Shopify Files. Includes future TCG placeholders (lorcana, yugioh, digimon, gundam) with empty images. See `docs/STOREFRONT_CMS.md`.

## Technical Debt

1. **Documentation drift** — `docs/PROJECT.md` (and previously this audit) lag behind shipped Shopify cart, content pages, and dynamic collection routes.
2. **Offline JSON dual world** — importer still writes `data/*.json` + wholesale `cost` while storefront ignores them (intentional, but operational surface remains).
3. **Presentation helpers vs Shopify media** — templated descriptions/specs; single image; language fixed to Japanese.
4. **Release dates dual path** — slug map / title parse vs seeded `custom.release_date` metafield.
5. **Client-side collection filter/sort/pagination** — full product arrays in the browser; not Shopify Storefront filter API; not URL-stateful.
6. **Widespread `unoptimized` on `next/image`** despite Shopify CDN allowlist in `next.config.ts`.
7. **Duplicated availability/CTA logic** across ProductCard / QuickView / PurchasePanel.
8. **Reserved handles block game routes** for merch words (`accessories`, `account`, etc.) without corresponding pages where marketed.
9. **CMS accessories + hero secondary hash links** leftover from pre-route era.
10. **No middleware / custom `not-found` / `loading` / `error` files** — Next defaults only.
11. **`apply-pricing` orphaned** — useful for JSON dumps only; no npm script; less relevant with Shopify as sole runtime source.
12. **Unused merchandising collections at homepage** — `featured` / `best-sellers` / `sale` ensured but unused by rails.
13. **Sync ownership split** — prices/status/SEO merchant-owned after create; must be understood when debugging catalog (see `SHOPIFY_DATA_STANDARD.md`).
14. **`CollectionView` unused props** — `selectedGameLabel` / `selectedLanguageLabel` accepted but not used in body.
